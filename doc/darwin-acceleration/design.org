Both candidate clean samples show =dynamic_load -> dlopen -> mapSegments ->
fcntl=. Each is a one-second sample, not whole-command syscall timing. Owned fd
snapshots do not establish exact fd/syscall association. Source-unchanged timing
variation prevents attributing the full delay to the absent native gxpkg product.

The accidental extra run used =--step= with =--run=, which did not limit execution.
It was stopped and owned groups were reconciled. The framework now rejects that
combination before launch. Its times remain excluded from net-benefit claims.

* Acceptance still required
- Build and install the native command product through the existing official
  tools producer; preserve library imports and provider override semantics.
- Preserve positive and negative controls, natural exit, original package tests,
  worker/environment resolution and the8GiB charged-footprint contract.
- Complete =gerbil clean=, =gerbil build= and original tests for both gerbil-mcp
  and gerbil-poo before admitting matched cold/incremental net benefit.
- Do not convert sum-RSS or the charged-footprint ledger into exact physical RAM,
  multiply stack fractions by whole-command time, or count existing GCC gains again.
- QNT owns readiness/publication/custody histories; Lean owns binding, argv,
  representation and semantic refinement. Neither proves measured speedup.

* Evidence retention
Only source, this design note and the curated checkpoint are distributed.
Compiler copies, generated C/object products, raw logs and process caches remain
outside Git. Run IDs identify local execution history; their absence in a clean
checkout is missing native evidence, never a passed gate.
