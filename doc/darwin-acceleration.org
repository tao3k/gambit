The branch contains runtime code, not just build configuration:
- lib/os_exec.h owns a parent-prepared Darwin exec-image plan.
- lib/os_io.c consumes that plan and coordinates SIGCHLD with device topology.
- lib/os_io.h separates live devices from cleanup-owned devices.
- The original tests/check target includes the real private-plan native test.

Public object representation, FrameSpec, continuation and GC algorithms are
unchanged. The new process protocol does not grant general VM/FFI shutdown
qualification. Non-Darwin native execution and custom virtual release providers
still require their own acceptance.

* Exec-image plan
:PROPERTIES:
:CUSTOM_ID: EXEC-IMAGE-PLAN
:END:

The parent constructs file actions, attributes and copied PATH recipes before
fork. It does not resolve executable files ahead of the child's real cwd.
The child retains the original interrupt cleanup, affinity reset, redirection,
chdir and environment transitions. Eligible image replacement uses SETEXEC and
CLOEXEC_DEFAULT; no child-side plan allocation is needed.

This extends the previous explicit-path/all-standard-fds-open path to bare
names with an explicit child environment and closed/CLOEXEC standard fds.
Empty and relative PATH entries are interpreted after the actual child chdir.
The fd snapshot precedes pipe allocation, so pipe reuse of a closed standard
number cannot become accidental stdio inheritance. Redirection supplies the
corresponding standard fd before the kernel actions run.

PTY remains on the original path. Preparation failure releases private plan
storage and uses the original path. Failed replacement retains execvp handling,
including ENOEXEC shell fallback and the original errno-pipe delivery. The plan
has idempotent private destruction; no global plan cache or new public ABI.

Fork is deliberately retained: Gambit's legacy interrupt cleanup includes
dispositions that a direct parent-side spawn must not silently change.
The existing production kernel-fd-closure optimization is baseline credit.
Only newly admitted paths may contribute new savings.

* Child status and device custody
:PROPERTIES:
:CUSTOM_ID: CHILD-STATUS-CUSTODY
:END:

A lock-free control word coordinates normal topology ownership and pending
SIGCHLD notification. A handler does not wait for an interrupted owner or invoke
a virtual provider. Reaping examines both live and cleanup-owned rings under
the same claim; an already completed device with a recycled PID is not the
recipient of a new child's status. Process-status fields use atomic access.

Cleanup moves a device to a distinct owned ring before releasing topology
access. A failed close/select returns it to live custody; settled release is
distinct from a provider error. Cancellation restoration follows relinquishing
ownership. Group/module cleanup retains unresolved devices rather than freeing
their outer owner and losing the internal responsibility.

This integrates the earlier isolated native-device design into current
modern-c without copying its obsolete global arena or frame/GC changes.

* Complete compiler and package gate
:PROPERTIES:
:CUSTOM_ID: PACKAGE-ACCEPTANCE
:END:

Only the complete Gerbil compiler built from this branch can admit the candidate:
#+begin_example
gerbil clean
gerbil build
<original repository test entry>
#+end_example

Run that sequence for gerbil-mcp and gerbil-poo, preserving stage budgets,
test populations and source/dependency identities. Homebrew remains an
independent reference, not a fallback candidate or matched three-switch pair.

Pending source dependencies include the VM global-storage contract: current
modern-c shares ordinary globals, primitive overrides and presence bits in one
fixed allocation. Any growth migration must cover all three and existing root
consumers; the earlier ordinary-only segmented arena is not suitable.

StaticModuleProduct/LinkPlan integration and whole-package cold/incremental
timing remain open. No full package acceptance, twofold speedup or merge is
claimed by these native results.
